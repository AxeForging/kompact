laya‑compact

Claude Code compacts by asking a model to summarise your session. This scores every tool call instead and deletes only what is no longer needed verbatim, on your machine, with no API key, no GPU and no network call. The optional Laya sidecar is the one path that uses either.

01Evidence

It replaces a neural model that it beat.

The plugin started as a port onto Laya, a 322M-parameter decision model that runs locally. Measured against 1,063 tool calls labelled from 18 real sessions, a twelve-coefficient logistic regression over facts already computed for free beat every Laya checkpoint and question wording.

The built-in scorer won 10 of 10 paired splits, by +0.174 on average and by +0.002 on the closest.

Every scorer judged on the same held-out sessions each split, so the comparison is paired. Splitting by session, not by row: calls inside one session are correlated and splitting on rows would leak. Calibration error 0.019 against Laya’s 0.42–0.71, which is what makes the keep-threshold mean anything.

02Watch it decide

Nine calls, two probabilities each, one ranking.

A session that finds a test failing only on CI, tracks it to a timezone in a fixture, and fixes it. Press the button and the calls are decided in the order the scorer ranks them, lowest first, until half the droppable output is freed.

    The transcript is constructed — every real session on this machine is someone's work and this page is public. The decisions are not: the list is produced by running the shipped scorer with the shipped defaults, and nothing in it was chosen by hand. Regenerate it with npm run docs:demo.

    The Edit it wanted to delete

    The first time this ran, the scorer dropped the Edit that fixed the bug. Both its scores were low and honestly so — “Applied 1 edit to src/auth.ts” is worth nothing, and exactly 1 of the 138 mutating calls in the corpus had an output that was ever needed verbatim. But the input is the only record that the change happened, and unlike a read it cannot be recovered by running it again.

    So a mutating call is no longer the scorer’s decision. Edit, Write, MultiEdit and NotebookEdit keep their call whatever the probabilities say; only their output can go. Across the corpus that rescues 21 of 138 such calls, leaves reused-output retention unchanged at 84.6%, and moves freed from 42.9% to 43.0%, because the budget then continues down the ranking.

    Why it frees a fifth and not four fifths

    The scorer produces a ranking, and the ranking holds up on sessions it has never seen. An absolute probability cut does not, because every session has its own mix of tools and so its own distribution: a Bash-heavy session scores low throughout, and a fixed cut sweeps all of it. Barely 7% of tool outputs are ever reused verbatim, so a well-calibrated scorer seldom passes 0.5 even for the ones that matter.

    Calls are therefore dropped lowest-score-first only until the reduction target is met, with the keep threshold acting as a floor that nothing is dropped above. Simulated per session on the labelled corpus, scored leave-one-session-out:

    Freeing nearly everything is easy and nearly worthless. Run through the shipped code rather than this simulation, the same defaults give 43.0% freed and 84.6% kept; the difference is the one rule the sweep has no notion of, which is that a call recording a change is never dropped. Calibrating on your own sessions is an accuracy upgrade rather than a prerequisite, because the policy adapts to your distribution on its own.

    04Where it loses

    The model we dropped fails quietly, which is worse than failing.

    Laya’s English checkpoint reads 512 tokens and discards the rest with HTTP 200 and no warning. Padding one decisive sentence with unrelated filler, the same question was asked of a 4,278-character state and a 21,078-character state:

    Bit-identical. Five times the input, the same answer — and 0.41 for a fact the text stated verbatim, which is the wrong side of any threshold. Both upstream projects send the whole conversation, up to 25,000 tokens, as one state.

    What the other 15.4% costs

    “84.6% of reused outputs kept” invites you to supply your own answer for the rest, so here it is, priced. Held-out scores, shipped policy, per session: 10 of the 78 reused outputs are dropped and actually shortened — 0.56 a session. Two more are dropped but short enough to sit inside the retained head, so nothing is removed at all.

    None of the ten kept a head, because both scores were low enough to drop the call outright. Nine of the ten are command output that a later tool input quoted verbatim — the shape this scorer is worst at, since tool=Bash carries a −1.36 coefficient because most command output is never referred to again, and the minority that is gets swept along. This is recovery cost, not task outcome; see the ledger below.

    Three more things this does not do

    A summary compresses harder. Freeing a fifth of the tokens is less than replacing the conversation with a few thousand tokens of prose. What you buy with the difference is not re-running tools to recover what a summary threw away.

    One feature does most of the work. Output size alone scores 0.876 with a quarter of the variance. The other coefficients earn their place on characters freed at a given safety level, not on ranking.

    It has never seen a Grep. The corpus contains no Grep and no Glob call at all, so that feature never fired during fitting and its weight is 0.0 — zero by absence, not by measurement. A search falls to the reference level, alongside WebFetch and Agent, about which this scorer also knows nothing. Thirteen features were defined; twelve were fitted.

    The shipped coefficients are one person’s sessions. A different tool mix scores differently and nothing detects that for you, so npm run calibrate refits on your own transcripts and reports whether it helped.

    05Verification

    Including the one that was not.

    Beats the model it replaces

    1,063 labelled calls, 18 sessions, 10 grouped splits, paired. eval/repeat.ts

    No orphaned tool call survives

    Run over a real session from disk. An orphan is rejected by the API and would break the session compaction was meant to save.

    Prose is never touched

    Same real-session test: only tool calls and results are dropped or truncated.

    A dead scorer cannot break a session

    Falls back to the built-in summary; a single failed request keeps its call.

    Works for Codex CLI, against a fixture

    jev-compact’s own parser, scorer and HTTP client driven over its recorded rollout fixture against our server. Not run against a live Codex: that plugin needs Codex ≥ 0.155 and this machine has 0.131.

    Task outcome

    Every figure on this page is tokens, ranking or recovery cost. Whether the assistant still finishes the job after a compaction has not been measured; that needs the same session replayed both ways and the following tool calls compared.

    The engine calling session.compact live

    The plugin loads and turn.complete fires in a real session, but the engine declines to compact below ~31% full and the model cannot invoke /compact itself. Covered by the real-session test; the engine-side handoff is not.

    07FAQ

    The questions a sceptic asks.

    Isn't this just a heuristic with extra steps?

    It is a heuristic with error bars, which is the difference. Thirteen coefficients fitted on labelled data, evaluated on sessions held out whole, calibrated well enough that the threshold means a probability — expected calibration error 0.019. “Big outputs get reused” alone reaches 0.876, so most of the signal really is one feature; the other twelve earn their place on characters freed at a fixed safety level, not on ranking.

    Why did the neural model lose?

    It was asked to read facts as prose that the features encode directly, and it was never trained on this task. Laya's own documentation says the base checkpoints sit near chance on typed-decision workflows and should be treated as a fast base to specialise. That is what was measured, and the wording mattered more than the checkpoint: on typed-decisions, asking what is true of the text scores 0.721 where asking what to do scores 0.419.

    Will it delete something I need?

    Sometimes — 0.56 outputs a session, measured above, and nine of ten of those are command output. A dropped result keeps its first 300 characters when the call survives, and a call that recorded a change is never dropped at all. Every failure mode falls back to Claude Code's own summary rather than to a half-compacted transcript, and a single failed request keeps its call: a wrong keep costs context, a wrong drop costs work.

    Do I have to calibrate?

    No. An earlier version effectively did, because an absolute probability cut cannot survive a distribution it was not tuned on. Dropping lowest-score-first until a character budget is met adapts on its own, so npm run calibrate is an accuracy upgrade. It is still worth running: the shipped coefficients come from one person's 18 sessions.

    How is this different from the built-in /compact?

    The built-in asks a model to summarise the session and replaces it with prose, which compresses far harder than a fifth. This keeps what survives verbatim, so a file you read is still the file, not a description of it. It is not a better compressor; it is a different trade — and it hands the session back to the built-in summary whenever it cannot do its job.

    08Install

    Function hooks are early access, so turn them on first.

    Needs Claude Code 2.1.281 or newer, where function hooks exist. On an older build the plugin installs and silently never runs, so check claude --version first.

    shell — copy all four lines

    export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1

claude plugin marketplace add AxeForging/laya-compact
claude plugin install laya-compact@laya-compact

    It replaces compaction rather than repairing it: Claude Code’s session.compact hook returns a replacement message list. Any failure at all (scorer down, malformed response, or a saving below the minimum) falls back to the built-in summary.
