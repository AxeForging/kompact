laya‑compact

Claude Code compacts by asking a model to summarise your session. This scores every tool call instead and deletes only what is no longer needed verbatim, on your machine, with no API key, no GPU and no network call. The optional Laya sidecar is the one path that uses either.

Result

It replaces a neural model that it beat.

The plugin started as a port onto Laya, a 322M-parameter decision model that runs locally. Measured against 1,063 tool calls labelled from 18 real sessions, a thirteen-coefficient logistic regression over facts already computed for free beat every Laya checkpoint and question wording.

The built-in scorer won 10 of 10 paired splits, by +0.174 on average and by +0.002 on the closest.

Every scorer judged on the same held-out sessions each split, so the comparison is paired. Splitting by session, not by row: calls inside one session are correlated and splitting on rows would leak. Calibration error 0.019 against Laya’s 0.42–0.71, which is what makes the keep-threshold mean anything.

Why it frees a fifth and not four fifths

The scorer produces a ranking, and the ranking holds up on sessions it has never seen. An absolute probability cut does not, because every session has its own mix of tools and so its own distribution: a Bash-heavy session scores low throughout, and a fixed cut sweeps all of it. Barely 7% of tool outputs are ever reused verbatim, so a well-calibrated scorer seldom passes 0.5 even for the ones that matter.

Calls are therefore dropped lowest-score-first only until the reduction target is met, with the keep threshold acting as a floor that nothing is dropped above. Simulated per session on the labelled corpus, scored leave-one-session-out:

Freeing nearly everything is easy and nearly worthless. A dropped result usually keeps its first 300 characters, but not always: when a result scores below the floor the call often does too, and then it goes entirely. Of 14 wrongly dropped outputs, 2 kept a head. This is also why calibrating on your own sessions is an accuracy upgrade rather than a prerequisite, since the policy adapts to your distribution on its own.

Where it loses

The model we dropped fails quietly, which is worse than failing.

Laya’s English checkpoint reads 512 tokens and discards the rest with HTTP 200 and no warning. Padding one decisive sentence with unrelated filler, the same question was asked of a 4,278-character state and a 21,078-character state:

Bit-identical. Five times the input, the same answer — and 0.41 for a fact the text stated verbatim, which is the wrong side of any threshold. Both upstream projects send the whole conversation, up to 25,000 tokens, as one state.

Three more things this does not do

A summary compresses harder. Freeing a fifth of the tokens is less than replacing the conversation with a few thousand tokens of prose. What you buy with the difference is not re-running tools to recover what a summary threw away.

One feature does most of the work. Output size alone scores 0.876 with a quarter of the variance. The other twelve coefficients earn their place on characters freed at a given safety level, not on ranking.

The shipped coefficients are one person’s sessions. A different tool mix scores differently and nothing detects that for you, so npm run calibrate refits on your own transcripts and reports whether it helped.

Verification

Including the one that was not.

Beats the model it replaces

1,063 labelled calls, 18 sessions, 10 grouped splits, paired. eval/repeat.ts

No orphaned tool call survives

Run over a real session from disk. An orphan is rejected by the API and would break the session compaction was meant to save.

Prose is never touched

Same real-session test: only tool calls and results are dropped or truncated.

A dead scorer cannot break a session

Falls back to the built-in summary; a single failed request keeps its call.

Works for Codex CLI, against a fixture

jev-compact’s own parser, scorer and HTTP client driven over its recorded rollout fixture against our server. Not run against a live Codex: that plugin needs Codex ≥ 0.155 and this machine has 0.131.

The engine calling session.compact live

The plugin loads and turn.complete fires in a real session, but the engine declines to compact below ~31% full and the model cannot invoke /compact itself. Covered by the real-session test; the engine-side handoff is not.

Install

Function hooks are early access, so turn them on first.

Needs Claude Code 2.1.281 or newer, where function hooks exist. On an older build the plugin installs and silently never runs, so check claude --version first.

shell — copy all four lines

export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1

claude plugin marketplace add AxeForging/laya-compact
claude plugin install laya-compact@laya-compact

It replaces compaction rather than repairing it: Claude Code’s session.compact hook returns a replacement message list. Any failure at all (scorer down, malformed response, or a saving below the minimum) falls back to the built-in summary.

A derivative of tamaratran/fast-jev-compaction and fatelei/jev-compact, both MIT, which do this with TypeSafe’s hosted Jev model. Laya is Apache-2.0. This is MIT, by AxeForging: source and the full evaluation.
